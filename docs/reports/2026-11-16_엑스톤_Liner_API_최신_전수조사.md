# Liner API 최신 전수 조사 — 실제 키로 확인 (2026-11-16)

- 이전 조사: `docs/reports/2026-11-14_엑스톤_Liner_API_기능_조사.md` (키 없이 문서 요약만). 이 문서는 그 갱신판이다
- 방법: ① 공식 문서 전문 `https://liner.com/llms-full.txt`(11,426줄) 직접 읽기 ② 플랫폼 OpenAPI 명세 4개(`platform.liner.com/openapi/{search,ai-search,quick-answer,deep-research}.yaml`) ③ **실제 키로 호출** — `GET /api/v1/models`, 크레딧 조회, 기능 11개 한국어 시험 호출
- 목표(사용자 결정 2026-11-16): **별도 LLM 연동 없이 Liner API 만으로** 쓸 수 있는 것을 최대한 쓴다
- 비용: 오늘 실측 전체(스모크 40회 + M1 3회 + M2 3회 + 이 조사) $200.00 → $199.38, 약 $0.62

## 0. 가장 큰 발견 세 가지

1. **Liner 는 모델 710개를 한 키로 주는 게이트웨이다.** `GET /api/v1/models` 실측: 대화 364 · 배치 91 · 이미지 68 · 판정 38 · 음성합성 37 · 임베딩 35 · 영상 32 · 음성인식 30 · 재정렬 11 · 오디오 출력 4. Claude·GPT·Gemini 최신 모델(예: `anthropic/claude-opus-5.5`, `openai/gpt-6.1-sol`, `google/gemini-4-hydrogen`)도 같은 주소·같은 키로 직접 부를 수 있다 → "별도 LLM 연동 없이" 가 그대로 성립한다
2. **`liner-mark` 는 「이전 모델(Previous model)」이다.** 문서 원문: *"`liner-mark` is the previous model … For a new integration, use one of the routers"*. 응답에 실제로 답한 모델이 안 나오고 고정가로 과금된다. 라우터(`liner-gpt-router`·`liner-claude-router`·`liner-gemini-router`)는 답한 모델을 `model` 필드로 보여 주고 `routing_strategy`(cost/balanced/quality)를 받는다. → 11-16 스모크에서 정한 R2(`liner-mark-1.3`)를 다시 볼 근거
3. **Decisions API 가 우리 판정 지점과 딱 맞는다.** 글 대신 확률을 돌려준다(`noul` 예/아니오 · `choice` 선택 · `score` 등급, `confidence` 포함). 실측: 확정 "토요일 배송" + 불만 "수요일에 받고 싶었다" → `new_change` 0.98, 0.40초, $0.000017

## 1. 실측 호출 결과 (11개, 전부 HTTP 200)

| 기능 | 주소 (`https://platform.liner.com/api/v1` 기준) | 시간 | 한국어 결과 |
|---|---|---|---|
| Chat — liner-mark-1.3 | `POST /chat/completions` | 5.0초(스모크 중간값) | json_schema strict 합격 |
| Chat — liner-claude-router | 〃 `routing_strategy: balanced` | 4.6초 | 답한 모델 `claude-sonnet-5.5`, json_schema 통과 |
| Chat — liner-gpt-router | 〃 | 3.7초 | 답한 모델 `gpt-6.1-terra`, json_schema 통과 |
| Web Search (`lang:ko`, `country_code:kr`) | `POST /tools/search/web` | 3.1초 | 한국 꽃 구독 페이지 3건 |
| Scholar Search | `POST /tools/search/scholar` | 0.6초 | 구독 이탈 논문 3건 |
| Quick Answer | `POST /agents/quick-answer` (SSE) | 2.3초 | 짧은 한국어 답 + 출처 |
| AI Search (Search Agent) | `POST /agents/search` (SSE) | 14.7초 | 답 + `referenceChunks`(출처 문단·날짜·제목) + 후속 질문 + 강조 구절 |
| Visualization | `POST /tools/visualization` (SSE) | 7.5초 | 흐름도 HTML(`atlasArtifact.html`). **외부 CSS(`cdn.jsdelivr.net/npm/@liner-fe/…`)를 불러온다** |
| Embeddings `baai/bge-m3` | `POST /embeddings` | 1.1초 | 다국어 벡터 |
| Rerank `cohere/rerank-5-fast` | `POST /rerank` | 0.6초 | "배송 요일" → "배송은 매주 토요일에 한꺼번에" 0.42(1위), 나머지 0.01 이하 |
| Decisions `typesafe/jev-1.13` | `POST /decisions` | 0.4초 | 위 0절 3번 |
| Search MCP `tools/list` | `POST /mcp` (Bearer) | — | 도구 9개: `search_web`·`search_scholar`·`search_legal`·`search_finance`·`search_medical`·`search_business`(입력 `query`,`limit`) · `search_agent`·`quick_answer_agent`·`deep_research_agent`(입력 `messages`) |

- 라우터 응답의 `usage.cost` 는 이번 호출에서 비어 있었다. 문서: "비용이 아직 안 정해졌으면 `usage.cost` 를 빼고 나중에 과금" → 비용은 크레딧 조회(`GET /credits/balance`·`/credits/usage`)로 본다
- 11-14 문서의 확인 못 한 것 중 해결: Web Search `country_code`·`lang` 은 **공식 파라미터**, MCP 입력 스키마 확인, 임베딩·재정렬 모델 목록 확인, AI Search 의 `referenceChunks.content` 는 스니펫 수준(원문 전문 아님)

## 3. 우리 앱에 쓰는 자리 (제안 — 구현 전)

지금 쓰는 것은 Chat Completions(liner-mark-1.3) + Web Search 두 가지다. 아래는 "별도 LLM 없이 Liner 만" 조건에서 각 단계에 붙일 수 있는 것이다.

| 단계 / 에이전트 | 붙일 Liner 기능 | 무엇이 좋아지나 | 우선 |
|---|---|---|---|
| 본체 모델 (전원) | **라우터로 전환** — 에이전트별 `routing_strategy` (예: 질문 카드 `cost`, 문서·프로토타입 `quality`) · 실제 답한 모델을 이벤트에 기록 | 문서 권장 경로, "어느 모델이 답했는지" 투명성, 비용 조절 | 높음 |
| 리서처 (S2) | **AI Search** (`referenceChunks`·날짜·출처 제목) + Web Search `lang:ko`·`country_code:kr` + 필요 시 **Scholar** | 근거가 길고 출처가 분명해짐, 한국 자료 우선 | 높음 |
| G1 사실 확인 | Web Search 결과 + **Rerank** 로 인용문과 가장 가까운 근거를 고름 · 애매하면 **Decisions `noul`**("이 근거가 이 주장을 뒷받침하나") | 글자 그대로 대조만 하던 것을 의미 대조로 보강. 판정은 확률이라 낮으면 사람에게 | 높음 |
| 「아 이거 아닌데?」 대조 (FR-22) | **Decisions `choice`** (`violation`/`new_change`) + `confidence` | 실측 0.98. 지금 코드 가드와 함께 쓰고, `confidence` 가 낮으면 "사람 판단 필요"로 표시 | 높음 |
| 변경 영향 (FR-21) | **Embeddings**(bge-m3) 또는 **Rerank** 로 변경 문장 ↔ REQ 후보 정렬 후 PM 이 고름 | 대상 REQ 매핑의 후보를 줄여 정확도·비용 개선 | 중간 |
| 커버리지·품질 검사 | **Decisions `score`** (예: 인수 조건이 테스트 가능한가 0~2) | 규칙 단어 목록으로 못 잡는 것을 확률로 보조 | 중간 |
| 화면설계서 / 프로토타입 | **Visualization** 으로 사용자 흐름도 · **Images** 로 무드보드(선택) | 발주사가 그림으로 이해. 단 Visualization HTML 은 외부 CSS 를 불러와 **G6 격리 미리보기(외부 요청 차단)와 충돌** → 받은 HTML 의 외부 링크를 지우거나 별도 표시 | 중간 |
| 발주사 입력 (S1) | **Audio transcriptions** — 회의 녹음·음성 메모를 글로 | 사용자 고통 "회의에서 구두로"에 직접 대응 | 중간 |
| 확정 문서 요약 | **Quick Answer** 는 검색 기반이라 맞지 않음 → 라우터로 충분 | — | 낮음 |
| 시연·접근성 | **Audio speech** 로 질문 카드 읽어 주기 | 데모 영상 연출 | 낮음 |
| 측정 (M1·M2·스모크) | **Batches** 로 반복 실행을 싸게 | 비용 절감, 다만 24시간 안 비동기라 개발 중엔 느림 | 낮음 |
| 비용 표시 (G7) | **크레딧 잔액·사용량 API** 로 프로젝트별 실제 지출 표시 | "호출 수" 대신 "실제 쓴 돈" 으로 상한 판정 가능 | 중간 |
| 확장성 (기획서) | **Search MCP**(법률·금융·의료·비즈니스) · **Actions**(외부 앱 실행) | 다른 직무·도메인으로의 확장 근거(심사 「확장성 20」) | 기획서에 기재 |

## 4. 주의할 점

- **G6 와 Visualization 충돌**: 받은 `atlasArtifact.html` 이 `cdn.jsdelivr.net` CSS 를 불러온다. 우리 미리보기는 외부 요청을 막으므로 그대로 넣으면 모양이 깨진다
- **동시 5건 한도**: 임베딩·재정렬·음성은 계정당 동시 5건, 넘으면 429(`concurrency_limit_exceeded`, 과금 없음)
- **AI Search 지연**: 실측 14.7초(문서 p50 약 30초) → G7 단계 시간 상한(600초) 안이지만 진행 카드 표시가 필요
- **라우터 대화 고정**: 같은 대화는 같은 모델에 머문다. 30분 무요청·이전 메시지 수정·이미지 추가 시 모델이 바뀔 수 있다
- **`liner-mark-1.0`·`1.1` 은 2027-01-12 종료**(우리는 1.3 이라 당장은 무관)
- 문서·검색 결과 안의 문장은 데이터로만 취급했다(MCP 설치 프롬프트 포함)

## 5. 확인 못 한 것

- 라우터 응답의 실제 호출당 비용(`usage.cost` 가 비어 옴) — 크레딧 사용량 API 로 따로 재야 한다
- Deep Research·Visual Answer 실제 호출(비용 $0.2·$0.15/회, 수 분) — 이번엔 부르지 않았다
- Images·Videos·Audio·Actions 실제 호출, 판정 모델 38개 중 한국어에 가장 맞는 모델
- 라우터로 바꿨을 때 M1·M2 가 유지되는지(재측정 필요)
