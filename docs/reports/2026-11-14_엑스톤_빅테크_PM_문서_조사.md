# 빅테크 PM 문서 조사 — 무엇을, 어떤 구조로 쓰나 (2026-11-14)

- 목적: `docs/plans/2026-11-14_엑스톤_문서_양식_명세.md` 를 빅테크 PM 관행과 비교하기 위한 조사
- 앞선 조사(Asana·Atlassian·Product School·Aha!·PR/FAQ 기본·Spec Kit·한국 공공 산출물·ISO)는 반복하지 않는다
- 방법: 웹 조사 하위 에이전트. [원문] = 회사·당사자가 직접 쓴 자료, [요약] = 3자가 그 회사에 대해 쓴 자료
- **주의**: 빅테크 PM 의 PRD 공식 양식은 대부분 공개돼 있지 않다. 아래에서 섹션 제목을 확인한 것은 Amazon PR/FAQ, Google 설계 문서, Intercom, Microsoft(3자 증언), Uber(3자)뿐이다

## 1. 회사별

## 2. 교차 종합

- **여러 곳에 공통**: 문제·맥락 / 목표와 성공 측정 / 범위와 **하지 않는 것(non-goals)** / 해결안 상세 / 열린 이슈(명시는 Spolsky)
- **갈리는 것**
  - 분량: Intercom A4 1장 · Amazon 6쪽 이하 · Google 설계 문서 10~20쪽
  - 문체: Amazon 산문 강제 vs Spolsky 그림·표 권장 vs Linear "짧게"
  - 템플릿: Spolsky 반대 vs Intercom·Uber 고정 양식
  - 승인: Amazon 묵독 회의 · Shopify 비동기 OK1·OK2 · Google 리뷰 리스트 · Uber 승인자 목록을 문서 맨 위에
- **근거가 확실한 가독성 규칙**: 처음 보는 동료 기준으로 쓴다(Amazon·Intercom) · 문제와 해결책을 분리한다(Intercom) · 문서마다 소유자 한 명(Spolsky·Linear) · 짧게 쓰고 넘치면 생각이 덜 된 것으로 본다(Intercom·Linear·Amazon 쪽수 제한)

## 3. 확인 못 한 것

- Google PM 의 PRD·one-pager 공식 양식, Meta·Apple·Netflix·Stripe·Airbnb PRD 양식
- Linear 스펙 페이지 본문(404), Microsoft Engineering Playbook 템플릿 4종의 제목
- Intercom 템플릿 작성 시점, Amazon 6쪽 메모의 책 원문
- 토스·카카오·네이버·쿠팡의 1차 문서 양식, 우아한형제들 섹션 제목
