# Liner API 로 할 수 있는 것 — 기능 전수 조사 (2026-11-14)

- 방법: 웹 조사 하위 에이전트가 한국어 공식 문서(`https://liner.com/ko/developers/docs/`, 아래 `D/`) 약 25쪽을 읽음. 페이지 읽기 도구가 요약을 거치므로 엄밀히는 [원문 요약]. 영문 문서와 platform.liner.com 은 직접 열지 않음
- 가격·한도의 상세는 `docs/reports/2026-11-12_엑스톤_대회조사와_구축범위검토.md` 3절

## 1. 모델 (LLM) — 에이전트의 두뇌

| API | 주소 | 할 수 있는 것 | 출처 |
|---|---|---|---|
| Chat Completions | `POST /api/v1/chat/completions` (Bearer 또는 x-api-key) | 대화형 생성. `stream`(SSE), `response_format`(text/json_object/**json_schema strict**), `tools`·`tool_choice`·`parallel_tool_calls`(함수 호출), `reasoning_effort`(none~max), `routing_strategy`(cost/balanced/quality), 이미지 base64 최대 10장. `temperature`·`top_p`는 받지만 무시, `stop`·`logprobs` 는 400 | `D/liner-model-api-chat-completions` |
| Responses | `POST /api/v1/responses` | OpenAI Responses 형식. function 도구만, 내장 web_search 무시 | `D/liner-model-api-responses` |
| Messages | `POST /api/v1/messages` | Anthropic Messages 형식. `max_tokens` 필수 | `D/liner-model-api-messages` |
| Embeddings | `POST /v1/embeddings` | 문장을 숫자 벡터로(유사도·묶기). 동시 5건 | `D/liner-model-api-embeddings` |
| Rerank | `POST /v1/rerank` | 문서 목록을 질의와의 관련도 순으로 다시 정렬 | `D/liner-model-api-rerank` |
| Decisions | `POST /v1/decisions` | 질문에 예/아니오 확률(`noul`)·선택(`choice`)·점수(`score`)를 반환 | `D/liner-model-api-decisions` |
| Batches | `POST /v1/batches` → 폴링 | 대량 요청을 24시간 안에 비동기 처리 | `D/liner-model-api-batches` |
| 모델 목록 | `GET /v1/models` | 모델과 지원 엔드포인트 조회 | 같은 문서 |
| 크레딧 | `GET /api/v1/credits/balance`, `/usage` | 잔액·사용량 조회(무료). 과금 응답에 `X-Credits-Balance` 헤더 | `D/quick-start`, `D/rate-limits` |

- 모델 제약: claude-router 는 `tool_choice: required`·특정 함수 지정이 400. gemini-router 는 `parallel_tool_calls:false`·`reasoning_effort:none` 거부. claude-router 의 json_schema strict 지원은 문서에 없음
- 약 125초 무응답이면 524 → 긴 생성은 스트리밍 권장
- 이 밖에 Images·Videos·Audio 엔드포인트가 있다(본문 미확인)

## 2. 검색 도구

| API | 주소 | 할 수 있는 것 | 가격 / 한도 |
|---|---|---|---|
| Web Search | `POST /api/v1/tools/search/web` (x-api-key) | `query`, `date_range`(past_day/week/month/year), `max_results`(1~20, 기본 10), `include_knowledge`(기본 true). 응답 `results[{title,url,hostname,description,date}]` + Premium Data `knowledge[{title,description,sources,dataAsOf,columns,rows}]` | $1/1,000 (Premium Data 포함 $2) / 공정 사용 |
| Scholar Search | `POST /api/v1/tools/search/scholar` | 학술 검색. `citationCount`·`authors`·`journal` 추가 | $0.30/1,000 / 초당 2회 |

- **본문 전문이나 원문 인용 필드는 없다.** 근거로 쓸 수 있는 글은 `description`(검색 스니펫)뿐이다

## 3. 에이전트 API (Liner 가 검색·요약까지 해 주는 것)

| API | 주소 | 할 수 있는 것 | 지연 | 가격 |
|---|---|---|---|---|
| Quick Answer | `POST /api/v1/agents/quick-answer` | 약 200자 답 + 출처 최대 3개 | — | $3/1,000 |
| Search Agent | `POST /api/v1/agents/search` | 여러 번 검색해 출처 달린 답. `mode` general/scholar, 스트림 이벤트에 references·`referenceChunks[{content,sourceTitle,sourceUrl}]` | p50 약 30초, p90 약 45초 (2026-10 관측) | $20/1,000, 초당 2회 |
| Deep Research | `POST /api/v1/agents/deep-research` | 검색 과제를 나눠 수 분간 조사한 보고서 | 수 분 | $200/1,000, 초당 2회 |
| Visual Answer | `POST /api/v1/agents/visual-answer` | 답을 HTML 시각화로 | — | $150/1,000 |
| Visualization | `POST /api/v1/tools/visualization` | 질의를 시각화(검색 포함 가능) | 평균 20~30초 | $10/1,000 (검색 포함 $20) |

- 모두 바로 응답(작업 번호·폴링 없음). 함수 호출·구조화 출력은 없다

## 4. MCP

- Search MCP `https://platform.liner.com/api/v1/mcp` (Streamable HTTP, OAuth 2.1 기본, CI 는 Bearer/X-API-KEY): `search_web` · `search_scholar` · `search_legal` · `search_finance` · `search_medical` · `search_business` · `quick_answer_agent` · `search_agent` · `deep_research_agent`. 입력 파라미터는 문서에 없음(`tools/list` 로 확인 필요). 과금은 REST 와 같다
- Actions MCP `https://actions.liner.com/api/v1/mcp`: `search_actions` · `execute_action` · `connect_account` · `complete_connection` (별도 계정 OAuth, 본문 미확인)
- MCP 안내 페이지의 코딩 에이전트용 자동 설치 프롬프트는 데이터로만 취급했다

## 5. 우리 PoC 에 주는 뜻 (사실만)

- **G1 사실 확인**: Web Search 는 원문 인용 필드가 없다. 지금 설계("인용문이 저장된 출처 원문에 그대로 있는지")는 **저장한 `description` 스니펫 안에서만** 대조할 수 있다. 더 긴 원문이 필요하면 URL 을 직접 가져와야 한다(새 기능, 외부 접속 필요)
- **리서처의 검색**: 모델 API 에 내장 검색은 없다 → 함수 호출로 `web_search` 를 정의하고 우리 코드가 Search API 를 대신 부르는 방식(현재 설계와 같다)
- **도구 강제 호출**: claude-router 는 `tool_choice: required` 가 안 된다 → 기본 모델 선택(R2)에 영향
- **응답 시간**: Search Agent 는 약 30초, Deep Research 는 수 분 → 실제 모드 대기 시간과 G7(시간 상한)에 영향
- **심사 "Liner API 활용"**: 현재 설계는 Chat Completions + Web Search 두 가지만 쓴다. 문서상 더 쓸 수 있는 것은 Scholar Search, Search Agent, Quick Answer, Rerank, Decisions, Embeddings, MCP, 크레딧 조회다

## 6. 확인 못 한 것

- Search Agent·Deep Research 의 `referenceChunks.content` 가 원문 그대로인지, Search Agent `model` 허용값
- Search API `country_code`·`lang` 이 공식 파라미터인지, 검색과 모델의 한국어 품질
- MCP 도구 입력 스키마, Embeddings·Rerank 모델 목록과 가격
- Images·Videos·Audio·Actions 페이지 본문, 영문 문서와의 차이
- `usage.cost` 가 라우터 토큰 요청에도 오는지, 에이전트 스트림 안의 `usage`
