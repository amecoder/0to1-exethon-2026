# 한국 공공·SI 산출물 양식과 "처음 읽는 사람의 이해" 근거 조사 (2026-11-14)

- 목적: 문서 4종(BRD·PRD·화면설계서·테스트 케이스)을 **처음 보는 사람도 이해하고 전문가도 인정하는** 양식으로 만들기 위한 빈칸 조사
- 앞선 조사(`docs/reports/2026-11-12_엑스톤_개발문서_구조와_독자이해_조사.md`)에서 다룬 해외 PRD 템플릿·한국 화면설계서 관행·ISTQB·Spec Kit 은 반복하지 않는다
- 방법: 웹 조사 하위 에이전트(브라우저 검색, 원문 PDF 열람). [원문] = 1차 문서를 읽음, [요약] = 2차 자료

## 1. 한국 공공·SI 표준 산출물 양식

### 요구사항 (제안요청서 요구사항) — 과기정통부·NIPA 「공공 SW사업 제안요청서 작성을 위한 요구사항 상세화 실무가이드」(2021-01) [원문]
https://www.swit.or.kr/IS/web/isCbmRefView.jsp?ref_sq=1104&schCode=

- 「요구사항 내용 작성표」 7개 필드: ① 요구사항 분류 ② 고유번호 ③ 명칭 ④ 상세설명(정의·세부내용) ⑤ 산출정보 ⑥ 관련 요구사항 ⑦ 요구사항 출처
- ID 접두어 15종, 형식 `SFR-001`: SFR 기능 · PER 성능 · ECR 시스템장비구성 · INR 인터페이스 · DAR 데이터 · TER 테스트 · SER 보안 · QUR 품질 · COR 제약사항 · PMR 프로젝트관리 · PSR 프로젝트지원 · MPR 유지관리 수행 · MHR 유지관리 인력 · CNR 컨설팅 · ENR 공사
- 분류별 개수를 적은 **요구사항 총괄표**를 둔다
- BRD 에 해당하는 내용은 별도 문서가 아니라 제안요청서 앞부분: Ⅰ 사업개요(추진배경·필요성, 서비스 내용, 범위) · Ⅱ 시스템 현황 · Ⅲ 사업추진 방안 · Ⅳ 제안요청 내용(총괄표, 상세 요구사항). "비즈니스 요구 = 왜, 사용자 요구 = 무엇"으로 나눈다
- 지침: "수·발주자가 **모두 명확하게 이해할 수 있도록** 설명", 기능 요구와 비즈니스 요구를 분리

## 2. 국제 표준 (2차 자료)

- **ISO/IEC/IEEE 29148:2018** [요약] INCOSE NZ 발표자료(2025-11) http://www.extuitive.co.uk/papers/iso29148NzRequirements.pdf
  - 개별 요구사항 특성 9개: necessary · appropriate · unambiguous · complete · singular · feasible · verifiable · correct · conforming
  - 요구사항 묶음 특성 5개: complete · consistent · feasible · comprehensible · able to be validated
  - "무엇을, 어떻게가 아니라", 모호어 금지
  - 속성: 식별자 · 우선순위 · 근거(rationale) · 예상 난이도 · 품질 요구의 측정치 (다른 2차 자료는 owner·risk·type 도 든다)
- **ISO/IEC/IEEE 29119-3:2013 테스트 케이스(7.3.5)** [원문, 비공식 사본] https://wildart.github.io/MISG5020/standards/ISO-IEC-IEEE-29119-3.pdf
  - 고유 식별자 · 목적 · 우선순위 · 추적성 · 사전조건 · 입력 · 기대 결과 · 실제 결과와 판정
  - 입력의 상세도는 "**테스트 수행자의 지식에 맞춰** 조정"

## 3. 처음 읽는 사람의 이해 — 근거의 강도

| 방법 | 근거 | 강도 |
|---|---|---|
| **화면 목업을 곁들이기** | Ricca 외, ACM TOSEM 2014 — 통제 실험 4개·139명, 유스케이스에 목업을 더하면 이해 정확도·효율이 유의하게 크게 오르고 효율은 약 2배, 수행 노력 차이 없음 https://doi.org/10.1145/2629457 | **강함** (이 조사에서 가장 직접적인 수치) |
| 관점 기반 읽기(PBR: 역할별로 나눠 읽기) | Shull·Rus·Basili 2000 "개인·팀 결함 탐지율이 오른다"(수치 없음, 시간은 최대 30% 더) / 반례 Regnell 외 2000(30명) 유의차 없음 / UML 검토에서 PBR 69% vs 체크리스트 70% | 혼재 |
| 가독성 지수 | Flesch 공식은 한국어에 맞지 않음(샘플 2개에서 -60 대, 박정진 2018) / 영어권에서도 쉬운 문구로 고쳐도 이해도 차이 없던 연구(2007 학위논문) | 약함 — **쓰지 않는다** |
| 쉬운 우리말 지침 | 국립국어원 「쉬운 공문서 쓰기 길잡이」(2022, 2023-07 수정) 등 — 지침일 뿐 이해도 수치 없음 https://www.korean.go.kr/front/etcData/etcDataView.do?mn_id=&etc_seq=700&pageIndex=1 | 지침(효과 수치 없음) |
| Teach-back(읽은 사람이 자기 말로 다시 설명) | 의료 퇴원 지침 연구만 있음(2015). 요구사항 문서 적용은 유추 | 약함 |
| 요구사항 결함 자동 점검 | Femmer 외 "Requirements Smells"(JSS 2016) — 초록 수치 미확인 https://doi.org/10.1016/j.jss.2016.02.047 | 미확인 |
