# 기획서 「확장 가능성」 절 초안

> 작성 메모(기획서에는 넣지 않음): 2026-11-21 Codex 가 Fable 리뷰(갭 분석 결정 문서 5절)를 적용해 다시 썼고, Claude 가 사실 대조로 「14곳 모두가 갖춤」을 리서치 표현(「없는 곳은 없었다」)으로 고쳤다. 표의 「제출본에 있는 것」은 `submission-v1` 기준이며, 제출본에 없는 것을 있다고 쓰지 않는다. 업무 흐름 파일, 도구 등록부, 안전장치 목록 파일, 실행 기록 내보내기는 대회 기간 중 개선 브랜치 `feat/agent-os` 에서 구현·검증했고 제출본에는 넣지 않았다. 제출본을 `submission-v2` 로 올려 넣을지는 사용자가 정한다.

## 확장 가능성

다른 직무로 넓히려면 업무마다 달라지는 부분과 함께 사용할 부분을 나눠야 합니다. 0to1이 지금 실행하는 업무는 요구사항 하나입니다. 제출본은 에이전트와 팀 관계를 파일로 정의하고, 안전장치와 사람의 확인을 시스템 규칙으로 강제합니다. 이를 ‘에이전트 운영 계층’으로 삼아 확인·권한·상한·기록을 재사용하고자 합니다. 새 업무에는 흐름과 팀 파일뿐 아니라 단계별 지시문·출력 형식·검증 코드와 업무 화면도 필요합니다.

| 영역 | 제출본에 있는 것 | 확장 방향 |
|---|---|---|
| 에이전트·팀 | 역할·읽기와 쓰기 권한·모델 전략을 파일로 정의하고, 팀 관계 밖 메시지는 차단합니다. | 역할·권한·모델 전략은 파일에서 바꾸고, 새 직무는 할 일을 함께 등록합니다. |
| 사람 확인 | 다섯 확인 지점에서 승인 기록 없이는 다음 단계로 가지 않으며, 승인 시점의 판을 고정합니다. 확인 대기 상태는 저장되어 서버를 다시 켜도 이어집니다. | 업무에 맞게 확인 지점을 정합니다. 조사한 실행 체계 14곳 중 사람 승인이 없는 곳은 없었습니다. |
| 안전·비용 | 안전장치 G1~G9로 인용·민감 정보·용도를 검사하고 호출·시간·비용 상한을 둡니다. 예산 60%부터 저렴한 모델을 사용합니다. 조사한 30개 플랫폼·논문 중 비용 상한을 다루는 곳은 9개입니다. | 안전장치의 적용 지점·판정 방식·필요한 도구를 목록 파일로 선언합니다. |
| 기억 | 공유 원본과 실행 기록을 남깁니다. 기록을 재생하며, 중단된 단계는 사람이 재시도하면 처음부터 시작합니다. 설정에 따라 회사 자료·지난 결정·기존 서비스와 대조합니다. | 인증과 회사별 격리를 더합니다. |
| 도구·기록 | Liner 호출마다 누가·무엇을·걸린 시간을 기록하고, 모델 호출은 토큰과 비용까지 기록합니다. | 도구 등록부와 에이전트별 허용 도구를 두고, 실행 기록을 표준 형식으로 내보냅니다. |

회사의 기억을 더한 효과는 측정으로 확인했습니다. 회사 자료를 이어받게 하자 이미 답한 내용을 다시 묻는 질문 카드가 평균 3장에서 0장으로 줄었습니다. 기존 서비스와 대조하게 하자 같은 기능을 새로 만들자는 요구사항은 평균 5.5건에서 0건으로 줄었습니다(같은 예제로 2회씩 실행).

확장은 다음 순서로 진행합니다. 아래 구현·검증 결과는 모두 대회 기간 중 개선 브랜치에서 확인한 내용입니다.

1. **업무 흐름을 파일로 분리했습니다.** 가짜 Liner 응답으로 두 번째 흐름을 엔진 수준에서 끝까지 실행했고, 기존 테스트도 수정 없이 통과했습니다. 제품 화면에서 흐름을 선택하는 기능은 아직 없습니다.
2. **도구 등록부와 에이전트별 허용 도구를 구현했습니다.** 안전장치 목록 파일도 시작할 때 점검합니다. G1의 모델 확인에 FDE 리드의 결정 도구가 필요하다고 선언했으며, G1~G9 중 하나라도 빠지거나 필요한 도구가 없으면 서버가 시작하지 않도록 검증했습니다.
3. **실행 기록을 OpenTelemetry 표준 형식으로 내보냈으며, 다음으로 도구를 MCP로 받겠습니다.** 프로젝트 이름은 제외하고 누가·무엇을·걸린 시간·비용만 내보냅니다. 2026-11-21 로컬 Jaeger 2.1.0에 넣어 실행 구간 63개와 부모 연결이 모두 일치함을 확인했습니다. 조사한 실행 체계 14곳 중 실행 추적이 없는 곳은 없었고, MCP는 전체 30곳 중 23곳이 다뤘습니다.
4. **인증과 회사별 격리를 더하겠습니다.**

제출본은 요구사항 업무를 수행하는 범위이며, 개선 브랜치에서 구현·검증한 확장 기능은 제출본에 넣지 않았습니다.
