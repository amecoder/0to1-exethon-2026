# 에이전트 운영 계층(진짜 에이전트 OS) — 마감 전후 나누기 결정 (2026-11-21)

## 결정 (사용자 「그렇게 하자」, 11-21)

- **목표는 진짜 에이전트 OS**가 맞다. 다만 마감(11-25 23:59) 전에 이 출품작 안에서 완성하지 않는다.
- **마감 전**: 제출본은 「요구사항 에이전트」로 다듬는 데 집중한다. 기획서 확장성 절에는 지금 있는 운영 계층을 사실대로 쓰고, 남은 것은 로드맵으로 적는다(초안 `docs/plans/2026-11-21_엑스톤_기획서_확장성_초안.md` 에 이미 있음). 남은 결정은 개선분을 `submission-v2` 로 넣을지 하나(늦어도 11-24).
- **마감 뒤**: 진짜 OS 트랙을 따로 진행한다.

## 후속 결정 (같은 날, 사용자)

위 결정을 아래처럼 바꾼다. 이 절이 위 절보다 우선한다.

1. **지금까지의 에이전트 OS 개선분(`feat/agent-os`)을 제출 버전에 넣는다.** 사용자 기능 점검을 마친 뒤 `main` 에 합치고 태그 `submission-v2` 로 zip 을 다시 만든다.
2. 기획서 확장성 초안은 고칠 곳 없음.
3. **마감 뒤에 고친 코드로 결선 시연을 해도 된다**(사용자 확인). 다만 마감 뒤에 다시 제출할 수는 없다. 그래서 제출 zip 은 11-25 판으로 고정되고, 마감 뒤 작업은 결선 시연에만 쓰인다.
4. 시연 재녹화·기획서 PDF·영상은 개발이 끝날 때까지 대기.
5. **트랙 1~3번을 진행한다.** 순서: 사용자 기능 점검 → 점검에서 나온 문제 수정 → `submission-v2` → 트랙 1번부터.

## 왜 마감 전에는 하지 않나 (첫 결정의 이유 — 후속 결정 5번으로 대체됨)

1. 심사 기준(문제 정의 30 · 완성도 30 · Liner API 20 · 확장성 20)에서 운영 계층은 확장성 항목의 근거 정도로만 쓰인다. 시연 경로가 흔들리면 완성도 점수를 잃는다.
2. 진짜 OS인지 가르는 시험(아래 1번)이 남은 일 중 가장 크다. Fable 갭 분석 4절: 흐름을 프로젝트에 묶으면 화면 48곳·변경 요청·내려받기까지 함께 고쳐야 한다.
3. 11-24 는 zip 재생성·확인, 기획서 PDF, 5분 영상, 시연 재녹화에 써야 한다.

## 마감 뒤 트랙 — 순서와 통과 기준

| 순서 | 목표 | 통과 기준 |
|---|---|---|
| 1 | 두 번째 업무가 실제로 돈다 (갭 분석의 (b)) | **엔진 코드(`app/` 의 흐름 실행·도구·안전장치)를 고치지 않고** 성격이 다른 흐름 하나가 화면에서 끝까지 돈다. 후보: 문서 단계가 없는 짧은 흐름(씨앗 `flows/requirements_lite.json`). 갭 분석 4절의 순서대로: 흐름 id 를 프로젝트에 저장 → 확인 단계 검사를 흐름 파일 선언으로 → 레인·내려받기를 흐름의 역할로 → 화면이 단계 목록을 서버에서 받기 |
| 2 | 바깥과 표준으로 연결 (MCP, 그다음 A2A) | 다른 MCP 클라이언트가 0to1 의 흐름 하나를 도구로 불러 결과를 받는다 |
| 3 | 신원과 격리 | 실행 기록에 「누가 시켰는지」가 남고, 회사 A 의 실행이 회사 B 의 자료를 읽지 못함을 테스트로 보인다 |

- 구조 제안: 1번을 하면서 엔진을 별도 패키지로 떼어 내면 「0to1 은 그 위의 첫 번째 앱」이 코드에서도 드러난다.
- 갭 분석 4절에서 「안 함」으로 정한 것(스케줄러·큐, 벡터 장기 기억, 도구 호출마다 사람 승인)은 이 트랙에서도 필요가 생길 때까지 하지 않는다.

## 대회 규칙 확인 (공식 페이지 https://contests.liner.com/hackathon/exe-thon-2611/ , 규정 2026-11-02 시행, 11-21 직접 읽음)

- 제4조 2항: 출품작은 대회 기간(11-12~11-25)에 새로 만들었거나 크게 발전시킨 것이어야 한다.
- 결선(12-05)은 「팀당 10분 동안 에이전트를 시연하며 발표 + 질의응답 5분, 형식 자유」. 결선도 같은 네 기준으로 심사한다.
- **마감 뒤에 고친 코드를 결선에서 시연해도 되는지는 규정·FAQ 어디에도 적혀 있지 않다.** 제4조 2항을 보수적으로 읽으면 결선 시연은 제출한 판으로 하고, 마감 뒤 작업은 「이후 계획」으로만 말하는 것이 안전하다.
- 확실히 하려면 주최 측(규정 제12조의 문의 메일)에 물어야 한다. 밖으로 나가는 연락이라 사용자가 정한다.
