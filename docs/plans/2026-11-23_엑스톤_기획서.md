# 0to1(영일) 기획서

## 1. 문제 (누가 · 어떤 문제 · 얼마나 불편)

실제 소프트웨어 개발 프로젝트를 수행하면서 PM이나 기획자가 부재하거나, 담당자의 요구사항 분석 역량이 부족해 요구사항이 충분히 구체화되지 않은 상태에서 개발이 시작되는 경우를 자주 경험했습니다.

예를 들어, 꽃집을 운영하는 소상공인이 서비스 개발을 의뢰하면서 구두나 메신저를 통해 요구사항을 전달하지만, 기획자와 개발자가 제작한 결과물을 확인한 뒤 자신의 의도와 다르다는 의견을 전달하는 경우가 있습니다. 요구사항이 명확한 명세로 기록되어 있지 않으면 최초에 합의한 내용을 확인하기 어렵고, 반복적인 수정 작업으로 인해 프로젝트의 완료 시점도 불명확해집니다.

또한 담당자마다 문서에 대한 이해도와 작성 역량이 달라 산출물의 품질에도 편차가 발생합니다. 요구사항이 불명확하거나 문서 간 내용이 일치하지 않고, 예외 조건이나 완료 기준이 누락되는 경우가 대표적입니다. 이로 인해 개발자는 반복적으로 문서를 검토하고 피드백해야 하며, 요구사항이 변경될 때마다 기획자와 개발자가 관련 문서를 다시 확인하고 누락되거나 충돌하는 내용을 찾아 수정하는 데 많은 시간과 노력을 소비하고 있습니다.

이러한 문제는 개인의 업무 경험에 국한되지 않습니다. 전 세계 10개국 228개 조직을 대상으로 진행한 NaPiRE(국제 요구공학 실태조사, arXiv:1611.10288) 연구에 따르면, 다음과 같은 문제가 소프트웨어 개발 과정에서 주요 문제로 지목되었습니다.

- 불완전하거나 누락된 요구사항: 48%
- 프로젝트 수행팀과 고객 간 의사소통 문제: 41%
- 지속적인 목표 및 요구사항 변경: 33%
- 추상적이고 불명확한 요구사항: 33%
- 프로젝트 수행팀 내부의 의사소통 문제: 27%

이러한 문제는 AI 코딩 에이전트를 활용하는 개발 환경에서도 발생할 수 있습니다. AI가 코드를 빠르게 작성하더라도 불완전하거나 모호한 명세를 기반으로 개발할 경우, 요청자의 의도와 다른 기능이 구현되어 반복적인 수정과 검증이 필요하기 때문입니다.

따라서 소프트웨어 개발의 생산성과 품질을 높이기 위해서는 단순히 개발 속도를 높이는 것뿐만 아니라, 개발 초기 단계부터 요구사항을 명확하게 정의하고 문서 간 정합성을 검증하며, 이해관계자 간 합의를 체계적으로 관리할 수 있는 환경이 필요합니다.

## 2. 해결 방식

**0to1(영일)**은 구두로 전달된 요구사항을 이해관계자가 확인하고 합의한 최초의 개발 명세로 구체화하는 AI 멀티 에이전트 서비스로, 라이너 .EXE-THON 2026 출품작입니다. 발주사(요청자)가 메신저 대화, 메모, 회의 녹음, 이미지, PDF 등 다양한 형태로 요구사항을 전달하면 이를 원본 자료로 저장하고, AI 에이전트들이 협업하여 요구사항을 분석하고 구체화합니다.

조율자, FDE 리드(고객의 문제와 개발 범위를 정의하는 현장 중심 엔지니어), 리서처, PM, 디자이너, 개발자, QA 등 7개의 전문 에이전트와 소비자 에이전트가 참여하며, 사전에 정의된 팀 관계도에 따라 지정된 연결 내에서만 소통하고 협업합니다.

에이전트들은 요구사항의 불명확한 부분과 누락된 내용을 식별하고, 이를 질문 카드 형태로 구성하여 발주사에게 확인을 요청합니다. 모든 질문에는 ‘잘 모르겠어요’라는 선택지를 제공하여 발주사가 전문적인 지식이 없더라도 부담 없이 답변할 수 있도록 합니다. 또한 에이전트들이 협의를 통해 도출한 기본값을 별도로 제시하고, 발주사는 자신의 의도와 다른 항목만 수정할 수 있도록 합니다.

발주사는 기본 4회의 확인 절차와 변경 발생 시마다 1회의 추가 확인을 통해 요구사항을 확정합니다. 에이전트들은 이를 바탕으로 다음과 같은 산출물을 생성합니다.

- BRD(사업 요구사항 정의서)
- PRD(제품 요구사항 정의서)
- 화면설계서
- 테스트 케이스
- 프로토타입

프로토타입은 앱의 경우 모바일 기기별로, 웹의 경우 데스크톱부터 모바일까지 다양한 화면 환경에서 확인할 수 있도록 합니다.

확정된 요구사항과 이해관계자의 확인 이력은 기록으로 관리합니다. 요구사항이 변경되면 프로그램 코드가 변경 영향 범위를 산출하고, PM 에이전트가 이를 바탕으로 판단합니다. 이후 결과물에 대한 이의가 제기되면 기존 합의 기록과 대조하여 ‘기존 합의사항 위반’인지 ‘새로운 변경 요청’인지 구분합니다.

AI 에이전트의 판단 확신도가 낮은 경우에는 사람에게 판단을 위임하며, 최종 의사결정 권한은 프로그램 코드 수준에서 통제합니다. 또한 유해한 목적의 요청은 작업 시작 전에 차단하고, 에이전트 호출 횟수, 실행 시간, 비용이 사전에 설정된 상한을 초과하면 작업을 중단하고 사람의 확인을 요청합니다.

최종 산출물은 압축 파일 형태로 제공하며, 요구사항 및 설계 관련 문서 4종과 프로토타입, AI 코딩 도구가 활용할 수 있는 `AGENTS.md`, 결재권자의 의사결정을 지원하는 `제안요약.md`를 포함합니다. 본 서비스의 시연은 가상의 꽃집 ‘꽃님’을 대상으로 진행하며, 시연에 사용되는 모든 예제, 녹화 자료 및 평가 데이터는 직접 제작한 가상 데이터입니다.

## 3. Liner API 활용

0to1은 요구사항의 분석 및 구체화부터 산출물 생성, 사실 확인, 변경 영향 분석, 안전성 검증에 이르기까지 다양한 업무 단계에서 Liner API를 활용합니다.

모든 API 호출에 대해 담당 에이전트, 수행 작업 및 실행 시간을 기록하며, 모델 호출에 대해서는 발생 비용도 함께 기록하여 실행 과정의 추적과 비용 관리가 가능하도록 구성했습니다.

| 활용 영역 | Liner API | 주요 활용 내용 |
|---|---|---|
| 에이전트 협업 및 산출물 생성 | Router/Model API | 질문 카드, 요구사항, 문서 4종 및 프로토타입 생성, 변경 영향 매핑에 활용하며 응답에 사용된 모델을 활동 이력에 기록 |
| 리서치 및 근거 수집 | Search Agent API, Search API | 발주사의 사업 분야와 관련된 자료를 검색하고 출처 문단을 근거 자료로 저장. Search Agent API 호출 실패 시 Search API 활용 |
| 사실 확인 | Decisions API | 인용문 대조를 통과한 문장이 해당 근거 자료에 의해 뒷받침되는지 검증 |
| 요청 목적 및 안전성 검증 | Decisions API | 유해한 목적의 요청은 저장 전에 차단하고, 관련 단어가 포함되어 있더라도 정상적인 목적의 요청은 허용 |
| 합의사항 위반 및 변경 요청 판별 | Decisions API | 확정된 요구사항과 발주사의 이의 제기 내용을 비교하여 기존 합의사항 위반인지 새로운 변경 요청인지 판별하고 판단 확률을 반환 |
| 변경 요청과 요구사항 연결 | Rerank API | 변경 요청과 관련성이 높은 기존 요구사항 상위 5개와 관련성 점수를 PM 에이전트에게 전달 |
| 시각화 및 이미지 생성 | Visualization API, Images API | 화면 간 이동 순서를 흐름도로 시각화하고, 개발자 에이전트가 지정한 위치에 최대 3장의 이미지 생성 |
| 회의 녹음 분석 | Audio transcriptions API | 회의 녹음 내용을 텍스트로 변환하고 요구사항 분석을 위한 원문 자료로 저장 |

또한 무료로 제공되는 Credits API를 활용하여 업무 단계별 잔여 크레딧을 기록하고, API 호출 횟수와 실행 시간, 비용을 함께 관리합니다. 사전에 설정된 상한에 도달하면 작업을 중단하고 사람의 확인을 요청하도록 구성했습니다.

## 4. 성과

0to1의 핵심 기능에 대한 정확성과 안정성을 검증하기 위해 가상의 꽃집 데이터를 기반으로 기능별 평가를 수행했습니다.

요구사항 결함 탐지, 변경 영향 분석, 이의 제기 판별은 2026년 11월 16일 `liner-claude-router`를 사용하여 각각 3회 반복 측정했으며, 요청 목적 검증과 무관한 요청 필터링은 2026년 11월 18일에 측정했습니다.

평가 결과는 실제 고객을 대상으로 한 운영 성과가 아닌 소규모 표본을 활용한 기능 검증 결과이며, 모의 응답(Mock Response)을 사용한 실행 결과는 성과 지표에서 제외했습니다.

## 5. 확장 가능성

0to1의 주요 사용 대상은 외주 개발사와 사내 소프트웨어 개발 조직의 기획자 및 개발자, 그리고 서비스 개발을 의뢰하는 발주사와 현업 담당자입니다.

확정된 요구사항과 합의 내용을 `AGENTS.md`로 제공하여 AI 코딩 에이전트의 입력 자료로 활용할 수 있도록 구성했습니다. 이를 통해 요구사항 분석과 설계 단계에서 확정된 내용을 실제 소프트웨어 개발 단계까지 연계할 수 있습니다.

또한 업무 단계와 에이전트별 역할 및 권한을 파일 기반으로 정의하고, 비용이 발생하는 API 호출과 사용 가능한 도구는 별도의 등록부를 통해 관리합니다. 안전성 검증과 사람의 확인 절차는 시스템 규칙으로 강제하여 에이전트의 자율성과 통제 가능성을 함께 확보하도록 설계했습니다.

이러한 구조를 바탕으로 기존 소프트웨어 개발 업무뿐만 아니라 새로운 업무 프로세스로의 확장도 가능합니다. 다만 새로운 업무에 적용하기 위해서는 업무 단계별 프롬프트, 산출물 형식, 검증 코드 및 업무 화면에 대한 추가 개발이 필요합니다.

현재 요구사항 정의 단계까지만 수행하는 별도의 워크플로우는 모의 응답을 활용하여 실행 구조를 검증했으며, 사용자가 화면에서 해당 워크플로우를 선택하는 기능은 아직 구현하지 않았습니다.

향후에는 다른 AI 에이전트가 0to1의 기능을 직접 호출하고 활용할 수 있도록 외부 에이전트와의 연계를 확대하고자 합니다. 이를 위해 현재 공모전 제출본과 분리된 개선 브랜치에서 다음 기능을 구현하고 테스트하고 있습니다.

- **MCP(Model Context Protocol) 연계:** 외부 AI 에이전트가 0to1의 기능을 도구로 호출할 수 있도록 지원
- **A2A(Agent-to-Agent) 연계:** 외부 AI 에이전트와의 업무 위임 및 협업 지원
- **토큰 기반 신원 식별 및 기업별 데이터 분리:** 여러 기업이 서비스를 활용할 수 있는 환경을 위한 기반 마련

이를 통해 0to1을 독립적인 요구사항 분석 서비스에서 다른 AI 에이전트 및 개발 도구와 연계할 수 있는 서비스로 발전시키고자 합니다.

## 6. 기존 결과물과 새로 만든 부분

본 출품작은 기존에 개발된 결과물을 활용하거나 개선한 것이 아니라, 대회 기간인 2026년 11월 12일부터 신규로 개발한 결과물입니다.

서비스를 구성하는 소스 코드, AI 에이전트 프롬프트 및 관련 문서는 모두 대회 기간에 새롭게 작성했습니다.

FastAPI, React 등 공개 소프트웨어 프레임워크와 라이브러리는 의존성 버전을 고정하여 사용하고 있습니다.
