# 기능 점검 시나리오 — 에이전트 OS 개선본을 제출본에 넣기 전 (2026-11-21)

`feat/agent-os` 개선본(8100 서버, 코드 a095e05)을 `main` 에 합치기 전에 사용자가 직접 해 보는 점검표다.
정상 흐름과 예외 입력을 함께 본다. 기대 결과의 문구는 코드에서 그대로 옮겼다(11-21 확인).

## 0. 준비

- 주소: 맥에서는 `http://127.0.0.1:8100`, 다른 기기에서는 개인 사설망 주소의 8100 포트.
- 키 확인: `http://127.0.0.1:8100/api/liner/key-status` 를 열었을 때 `{"present":true}` 가 보여야 한다.
- 순서: A(비용 없음)를 먼저 하고, B와 C(비용이 아주 적음)를 거쳐 D와 E(실제 실행, 비용 큼)로 간다.
- 결과를 알려 줄 때는 번호로 적는다. 예: 「C3 OK, C7 이상: 카드번호를 넣었는데 그냥 보내졌음」.
- 비용 표기: 「없음」은 Liner 를 부르지 않는다. 「아주 적음」은 짧은 모델 호출 한두 번이다(정확히 재지는 않았다). 전체 실행 비용은 11-18·11-21 실측값이다.

## A. 비용 없는 점검

이 절은 개선 작업 때문에 제출본의 기본 기능이 깨지지 않았는지, 그리고 새로 생긴 운영 계층이 보이는지를 본다. A2·A3 은 터미널에서, 나머지는 브라우저에서 한다.

| 번호 | 하는 법 | 기대 결과 |
|---|---|---|
| A1 | 처음 화면에서 「시연 모드」를 누르고 끝 장면까지 넘긴 뒤 결과물 zip 을 내려받는다 | 오류 없이 끝 장면까지 간다. 제출본 확인 때 zip 안 파일은 22개였다 |
| A2 | `uv run python -m app.flow; echo "rc=$?"` (저장소 폴더에서) | `OK requirements`, `OK requirements_lite` 두 줄과 단계 목록, 마지막에 `rc=0` |
| A3 | `sed 's/"stages"/"stagez"/' flows/requirements_lite.json > "$TMPDIR/bad.json" && uv run python -m app.flow "$TMPDIR/bad.json"; echo "rc=$?"` | `X …bad.json: stages 가 비어 있어요` 와 `rc=1` |
| A4 | 브라우저로 `/api/tools` 를 연다 | Liner 호출 9종(도구 6종, 모델, 음성, 첨부 읽기) |
| A5 | 브라우저로 `/api/guardrails` 를 연다 | G1~G9 아홉 개. G7 제목에 「비용은 잔액을 못 읽으면 걸리지 않음」 |

## B. 회사 만들기와 회사 자료 (비용 없음)

처음 화면의 회사 칸에서 한다. 여기서 만든 회사와 자료는 D·E 에서 그대로 쓰니까 B5 까지 마치고 넘어간다.

| 번호 | 하는 법 | 기대 결과 |
|---|---|---|
| B1 | 「새 회사」로 「점검 꽃집」을 만든다 | 회사가 생기고 선택된다 |
| B2 | 이름을 비우거나 띄어쓰기만 넣고 만든다 | 만들어지지 않는다. 서버 문구는 「회사 이름을 적어 주세요」 |
| B3 | 이름에 61자 이상을 넣는다 | 만들어지지 않는다(상한 60자) |
| B4 | 「회사 자료」에 `담당자 연락처 010-1234-5678` 을 적고 「회사 자료 저장」 | 저장되지 않는다. 「회사 자료에 민감 정보로 보이는 것이 있어요(전화번호). 지우거나 가린 뒤 다시 저장해 주세요」 |
| B5 | 회사 자료를 `결제는 카드만 받는다. 배송은 서울만 한다.` 로 저장한다 | 저장된다. E 단계에서 이 자료가 쓰인다 |
| B6 | 같은 이름 「점검 꽃집」으로 회사를 하나 더 만들어 본다 | 정해 둔 동작이 없다. 어떻게 되는지 적어 달라(확인 못 한 곳) |

## C. 요구 입력 예외 (실제 모드, 비용 없음 또는 아주 적음)

「실제 모드」로 새 프로젝트를 만들고 메모 칸에 아래를 하나씩 넣어 「팀에게 보내기」를 누른다.
각 경우마다 팀(S2)으로 넘어가지 않고 메모 칸 아래에 안내가 떠야 한다. 하나 끝나면 메모를 지우고 다음 것을 넣는다.

### C-1. 코드가 바로 거르는 글 (비용 없음 — Liner 를 부르기 전에 막는다)

|---|---|---|
| C1 | (빈 칸, 또는 띄어쓰기만) | 보내지지 않거나 「요청이 비어 있어요. 무엇을 만들고 싶은지 적어 주세요」 |

| C4 | `아아아아아아아` | 「같은 글자만 되풀이돼서 읽을 수 없어요…」 |
| C5 | `앱 만들어` | 「너무 짧아서 무엇을 만들지 알 수 없어요…」(글자 5개 미만) |

### C-2. 모델이 판정하는 글 (아주 적음 — 모델 호출 1번)

| C7 | `오늘 날씨 좋네요. 점심 뭐 먹을지 고민이에요.` | 읽기 어려운 요청으로 분류. 「무엇을 만들고 싶은지 읽기 어려워요…」 비슷한 안내 |

## E. 프로젝트 2 — 같은 회사의 두 번째 요구 (약 $1~1.5, 추정)

D 에서 CP4 까지 승인한 프로젝트가 있어야 한다. 그래야 그 프로젝트가 「이미 만든 서비스」로 잡히고, 거기서 정한 답을 이번 프로젝트가 이어받는다. CP2 까지만 보고 멈춰도 된다.

| 번호 | 하는 법 | 기대 결과 |
|---|---|---|
| E1 | 회사가 「점검 꽃집」인지 보고 「실제 모드」로 새 프로젝트를 만든다. 메모는 `원데이 꽃꽂이 클래스 예약도 받고 싶어요. 결제는 지난번처럼 카드로요. 수강생이 날짜를 고르고 사장님이 예약 목록을 봐요.` | 접수 확인을 통과한다 |
| E2 | S3 질문 카드를 본다 | D 에서 이미 답한 질문은 다시 나오지 않는다(11-21 측정 0건) |
| E3 | 같은 카드 묶음에서 「같은 앱에 넣을까요?」 카드를 찾는다 | 카드가 나온다. 직접 입력 칸이 없고 「따로 새로 만든다」, 「잘 모르겠어요」 같은 선택지만 있다 |
| E4 | 회사 자료(B5: 결제는 카드만)와 다른 답이 나오는 질문이 있으면 다른 쪽을 고른다 | E6 에서 고른 답이 이긴다 |
| E5 | CP2 에서 「팀 보기」를 고른다 | 회사 자료로 정한 답에 회사 자료 배지가 붙는다. 시스템 대조에 「기능 추가 / 연계 / 재사용」이 보인다 |
| E6 | E4 에서 고른 답이 요구사항에 그대로 들어갔는지 본다 | 다르면 이상(11-21 측정 0건) |
| E7 | 「발주사 보기」로 바꾼다 | `SRC-07`, `CMP-02` 같은 내부 번호와 QA 지적 문장이 안 보인다 |
| E8 | 메모에 앱 이름을 넣은 경우(`점검 꽃집 앱에 예약 기능을 넣어 주세요…`)로 하나 더 해 본다(선택, 약 $1 추가) | 이미 이름을 말했으니 「같은 앱에 넣을까요?」 카드는 나오지 않는다 |

## 직접 하기 어려운 것 (이미 확인함)

- 예상 못 한 오류가 나면 실행이 「작업 중」에 갇히지 않고 「실패」로 바뀐다(X1). 일부러 오류를 낸 서버에서 확인했고, 「다시 시도」로 S2 가 끝까지 돌았다.
- 호출 상한에 닿은 뒤 요구 입력을 보내면 「계속」 안내가 나온다(X2). 테스트로만 확인했다.
- 호출·시간·비용 상한 카드(G7)는 「Liner 호출 N회 / 상한 M회 — 상한 값은 제안값이에요(실측 전)」 모양이다. 상한까지 쓰려면 비용이 커서 시나리오에서 뺐다.

## 확인 못 한 곳

- B6(같은 이름의 회사)은 정해 둔 동작이 없다.
- C6~C9, C13~C15 는 모델 판정이라 매번 같다고 보장하지 못한다. G9 정답표 24건에서는 막아야 할 12건을 모두 막고 잘못 막은 것은 0건이었다(11-18, 2회).
- C1 의 빈 칸은 화면이 버튼을 막는지, 서버 안내가 뜨는지 확인하지 않았다.
- D16(새로 고침)은 이번 개선본에서 따로 재 보지 않았다.
- E 비용은 재지 않은 추정이다.
