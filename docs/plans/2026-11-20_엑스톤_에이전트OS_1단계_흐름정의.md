# 에이전트 OS 1단계 — 업무 흐름을 파일로 (2026-11-20)

## 0. 배경

사용자 결정(11-20): "agent os 하는 건 이미 지금 기능이 어느 정도 다 됐으니까, 제출용 하나 고정해 놓고 개선본으로 진행". 그래서 제출본은 `main` 의 태그 `submission-v1`(f31270c)로 고정했다. 개선은 `feat/agent-os` 에서 한다. 첫 일은 「엔진과 업무 나누기」다(사용자 「진행하자」).

지금은 요구사항 업무의 단계 순서(S1 → S2 → CP1 → … → CP4)가 `app/orchestrator.py` 의 `STAGE_TABLE` 에, 단계마다 돌릴 함수가 `Orchestrator._handlers` 사전에 코드로 박혀 있다. 다른 업무를 올리거나 순서를 바꾸려면 엔진 코드를 고쳐야 한다.

## 1. 바꾸는 것 (1단계 범위)

- 흐름 정의 파일 `flows/requirements.json`: 단계 id·종류(input/work/confirm)·제목·맡는 에이전트·반려 시 돌아갈 단계(rework)·돌릴 일(run 이름)
- `app/flow.py`: 흐름 파일을 읽고 **시작 전에** 검사한다 — 첫 단계는 input, id 중복 없음, 종류는 셋 중 하나, work 는 등록된 run 이름, confirm 의 rework 는 그보다 앞의 work 단계, agents 는 정의된 에이전트
- 일 등록부(run 이름 → 함수): problem(S2) · requirements(S3) · finalize(S4) · documents(S5) · prototype(S6). 엔진(Orchestrator)은 흐름 파일의 순서대로 등록부의 일을 부른다
- 기본 흐름은 `flows/requirements.json`. `Orchestrator(..., flow=...)` 로 다른 흐름을 줄 수 있다

범위 밖(다음 단계): CP 마다 다른 동작(CP1 기존 제품 선택, CP2 판 번호 등)과 S1 입력 처리는 아직 엔진 코드에 있다. 흐름을 고르는 화면·설정도 아직 없다.

## 4. 2단계 — 엔진에서 단계 번호 빼기 (2026-11-20 밤, Fable 5.2 결정 D6 c)

1단계 뒤에도 엔진에 단계 번호가 박혀 있어 번호만 다른 흐름 파일은 돌지 않았다. 확인 단계마다 다른 동작을 흐름 파일 선언으로 옮겼다. `on_approve`(승인할 때 할 일: snapshot·bind_version·clear_recheck·refresh_problem, `app/hooks.py`)와 `features`(그 확인에서 사람이 할 수 있는 일: build_or_buy·requirement_review)를 적고, 사람 입력 메서드(카드 답·제출, 고칠 점 보내기, 기존 제품 선택, 화면 줄이기)는 단계 번호 대신 역할(그 일을 돌리는 단계, 그 기능이 있는 확인)로 단계를 찾는다. 「답하지 않은 카드가 있으면 시작 못 함」은 `app/runs.py` 의 `PRECHECKS` 로 옮겼다. 새 프로젝트는 `empty_source(first_stage)` 로 흐름의 첫 단계에서 시작할 수 있다.
