# UI/UX 정돈 계획 — 「동작하는 PoC」에서 「솔루션처럼 보이는 제품」으로 (완료, 2026-11-15)

- 관련: `docs/plans/2026-11-14_엑스톤_PoC_BRD_PRD.md` 2-4절(화면 구성), `docs/plans/2026-11-14_엑스톤_문서_양식_명세.md`, 11-12 토론 합의 D4(한 앱 틀 + **역할 전환** + 영역 3개)

- 기능은 바꾸지 않는다. 같은 데이터·같은 API 위에서 **보이는 방식과 흐름**만 바꾼다(테스트 224개는 그대로 통과해야 한다)

## 0. 왜 하나

심사의 「완성도 30」과 5분 영상은 화면으로만 판단된다. 지금 화면은 기능은 다 보여 주지만, 처음 보는 사람이 **지금 어디까지 왔는지, 팀이 무엇을 하는지, 내가 무엇을 하면 되는지**를 한눈에 알기 어렵다. PoC 의 핵심인 「팀 협업」도 글자 목록으로만 지나간다.

## 2. 목표 모습 — 원칙 5개

1. **한 화면 한 질문**: 발주사 보기에서는 지금 해야 할 일 하나가 화면 중앙에 크게(질문 카드·컨펌). 나머지는 뒤로
2. **팀이 일하는 게 보인다**: 관계도 그림 위에서 지금 말하는 두 에이전트와 그 선이 움직인다. 기록은 사람 말로 요약, 원문은 펼쳐야 보인다
3. **역할별 밀도**: 발주사 보기 = 쉬운 말·ID 숨김(마우스를 올리면 보임) / 팀 보기 = ID·표·경고 전부 (같은 원본, 다른 표현 — FR-09)
4. **경고는 세 가지 모양만**: 막음(빨강, 버튼 잠금 이유 표시) · 사유 필요(주황, 입력칸 붙음) · 참고(회색, 접힘)
5. **영상에서 읽힌다**: 1280×720 에서 본문 16px 이상, 핵심 장면이 스크롤 없이 한 화면

## 4. 가설·벤치마크

| 항목 | 내용 |
|---|---|
| 가설 | 위 정돈을 하면, 처음 보는 사람이 작업대 화면 한 장만 보고 「지금 단계 · 지금 일하는 에이전트 · 내가 할 일」 세 가지를 답할 수 있게 된다 |
| 기준선 | U0 에서 현재 화면으로 측정(아래 지표 전부) |
| 판정 기준 | ① 점검표 12문항 중 10개 이상 통과(현재 값은 U0 에서) ② Lighthouse 접근성 90 이상 ③ 1280×720 에서 핵심 장면 6개(질문 카드·CP1~CP4·시연 장면)가 스크롤 없이 보임 ④ 기존 테스트 224개 전부 통과 — ①~④ 모두 충족하면 채택 |
| 측정 방법 | 같은 가짜 Liner 시나리오(꽃님 메모)로 같은 장면을 같은 폭에서 캡처 · Lighthouse(chrome-devtools) · 점검표는 캡처를 보고 작성자가 채점(한계: 자기 채점) |

**점검표 12문항 (제안)**: 지금 단계가 보인다 · 남은 컨펌 수가 보인다 · 지금 일하는 에이전트가 보인다 · 누가 누구에게 넘겼는지 그림으로 보인다 · 발주사 보기에 내부 ID 가 기본으로 안 보인다 · 발주사 보기에 전문 용어가 없다 · 내가 할 일이 화면 중앙에 하나다 · 경고가 세 모양으로 구분된다 · 막힌 버튼 옆에 이유가 있다 · 내부 상태값·영어 이벤트명이 안 보인다 · 1280 폭에서 표 열이 무너지지 않는다 · 시연 재생기에서 장면 단위로 이동된다
