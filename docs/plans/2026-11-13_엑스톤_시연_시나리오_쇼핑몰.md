# 시연 시나리오 — 가상 쇼핑몰 「온새미로몰」 (보류, 2026-11-13)

> **보류(2026-11-14 사용자 결정)**: 시연 소재는 꽃집 「꽃님」으로 돌아갔다. 이 문서는 지우지 않고 남긴다

관련: `docs/plans/2026-11-13_엑스톤_에이전트_팀_관계도.md`(팀·관계·가드레일)

- **용도**: 시연 모드에 재생할 기록을 만들 때 실제 모드에 넣는 입력. 영상의 처음부터 끝까지가 이 시나리오다
- **모든 내용은 가상이다**(대회 규칙 3). 회사·수치·인물은 지어낸 것이고, 실제 회사 정보는 쓰지 않는다. README 에 "가상 시나리오, AI 도움으로 작성"이라고 밝힌다
- **출발점**: 사용자 경험 — "고객 방문자 데이터를 분석해서 고객 연령에 맞는 UI/UX로 방문수를 늘리고 싶은데, 우리는 그 방법을 모른다"(쇼핑몰)
- **두 겹 구조**: 겉 자료는 팀 에이전트에게 처음 주는 것, 속마음은 발주사 역할을 하는 사람만 보고 **팀이 물어야만** 답한다. 묻지 않은 속마음은 끝까지 말하지 않는다

## 3. 속마음 — 발주사 역할만 본다 (팀이 찾아야 할 숨은 사실 10개)

판정: 팀의 질문·경고·문서에 아래 사실이 드러나면 "찾음". 대표 지표 「숨은 요구 탐지」의 정답표로 쓴다(정답 파일은 별도로 고정 예정).

| # | 유형 | 숨은 사실 | 팀이 찾게 되는 계기(예) |
|---|---|---|---|
| H01 | 진짜 목표 | 방문수가 아니라 **매출**이 목표다. 방문수는 팀장이 아는 유일한 지표라서 말한 것 | "방문수가 늘면 무엇이 좋아지나요?" |
| H02 | 완료 기준 없음 | "늘린다"의 목표치가 없다. 물으면 "3개월 안에 10월보다 15%" | "얼마나 늘면 성공인가요?" |
| H03 | 데이터 한계 | 연령은 **회원만** 안다. 방문자의 약 70%가 비회원이다 | "연령은 어디서 알 수 있나요?" |
| H04 | 원인 미확인 | **데이터는 있는데 분석할 줄 모른다**(쇼핑몰 솔루션 통계 화면, 회원 정보). 방문 감소 원인을 분석해 본 적이 없다. 검색 광고비를 8월에 줄였다 | "8월부터 줄었는데 그때 바뀐 게 있나요?" |
| H05 | 숨은 문제 | 진짜 이탈은 **결제 단계**다. 60대 고객이 본인 인증·결제 화면에서 포기한다(CS 말과 연결) | ④ CS 발언과 소비자 의견 |
| H06 | 충돌 | 팀장은 "연령별로 다르게", 대표는 "너무 바꾸지 마라" | ①과 ③ 대조 |
| H07 | 기술 제약 | 임대형 쇼핑몰 솔루션을 써서 **서버 코드를 고칠 수 없다**. 화면 디자인과 스크립트만 바꿀 수 있다 | "지금 쇼핑몰은 어떻게 만들어졌나요?" |
| H08 | 개인정보 | 연령으로 화면을 바꾸는 데 개인정보 문제가 있는지 아무도 확인 안 했다 | 가드레일 G1·G3, 리서처의 근거 검색 |
| H09 | 일정 | "다음 달 행사"는 6주 뒤 연말 기획전이다 | "다음 달 언제인가요?" |
| H10 | 기기 | 방문의 약 80%가 모바일인데, 팀장은 PC 화면만 보고 이야기했다 | "고객들이 주로 어떤 기기로 오나요?" |

## 5. 시연 모드에서 기대하는 흐름 (영상 뼈대 후보)

1. 발주사가 겉 자료 4개를 넣는다
2. 조율자가 FDE 리드·리서처에게 배정 → 질문 카드로 H01·H02·H03 등을 찾는다. 리서처는 Liner Search 로 근거(연령 맞춤 UI 사례, 개인정보 고려 사항)를 붙인다 — 출처 없는 내용은 "미확인"(G1)
3. 소비자 에이전트 의견으로 H05(결제 이탈)가 드러나고, 문제 정의가 "연령별 UI"에서 "**결제 이탈을 줄이고 연령에 맞춘 안내로 매출을 늘린다**"로 바뀐다
4. PM·디자이너·QA가 BRD·PRD·화면설계서·테스트 케이스를 만든다. 충돌 H06 은 미결로 올라 조율자가 발주사에게 묻는다
5. 발주사 컨펌(G2) → 개발자가 웹 프로토타입(예: 모바일 홈 + 쉬운 결제 화면 + 연령대별 안내 배너, 화면 5개 이하 G8)을 만들어 미리보기에 띄운다
6. 결정 로그와 미결 목록, 내려받기(HTML + 명세 zip)
